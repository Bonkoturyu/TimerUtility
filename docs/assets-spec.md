# Assets Specification

本プロジェクトに同梱する音源・画像等のアセットの仕様を定義する。
Phase 5 着手前に音源を準備すること。

## 音源仕様

### 共通要件

| 項目 | 要件 |
|---|---|
| フォーマット | MP3（推奨）または WAV |
| サンプリングレート | 44.1 kHz |
| ビットレート | 128 kbps 以上（MP3 の場合） |
| チャンネル | ステレオ |
| 長さ | **8〜15 秒**（ループ再生前提） |
| ファイルサイズ | 1 ファイル 500 KB 以下 |
| 音量 | -3 dB ピーク以下（クリッピング回避） |
| フェードイン / アウト | 推奨（ブツ切り音は避ける） |

### ループ再生

`audioplayers` の `ReleaseMode.loop` で繰り返し再生する。
ループ境界が滑らかになるよう、音源の最初と最後の波形を合わせる。

### 音量正規化

すべての音源を同じピーク音量に揃える（-3 dB 推奨）。
ユーザーが音源を切り替えても音量が大きく変わらないようにする。

## 同梱音源リスト（仮）

具体的な音源は Phase 5 着手時に最終決定。仮の構成例:

| ファイル名 | ID | 表示名（日本語） | 表示名（英語） | 特徴 |
|---|---|---|---|---|
| `alarm_default.mp3` | `default` | デフォルト | Default | 標準的なアラーム音 |
| `alarm_gentle.mp3` | `gentle` | やさしい | Gentle | 穏やかな起床向け |
| `alarm_warning.mp3` | `warning` | 警告 | Warning | 強めの注意喚起 |
| `alarm_chime.mp3` | `chime` | チャイム | Chime | 学校チャイム風 |
| `alarm_bell.mp3` | `bell` | ベル | Bell | 単音ベル |
| `alarm_digital.mp3` | `digital` | デジタル | Digital | 電子音 |

最低 5 種類、最大 10 種類程度を目安に同梱。

## ライセンス管理

### 採用方針

以下のいずれかから取得:

1. **Royalty Free / CC0 サイト**
   - Pixabay: https://pixabay.com/sound-effects/
   - freesound.org（CC0 限定で絞り込み）
   - Mixkit: https://mixkit.co/free-sound-effects/

2. **自作**

3. **商用利用可能なライセンス購入**

### ライセンス情報の記録

`assets/sounds/LICENSES.md` を作成し、各音源について以下を記録:

- ファイル名
- 出典（URL）
- 作者
- ライセンス名（CC0, CC BY 4.0 等）
- 取得日
- 加工有無

例:

```
## alarm_default.mp3
- 出典: https://pixabay.com/sound-effects/xxx/
- 作者: 〇〇
- ライセンス: Pixabay Content License (Royalty Free)
- 取得日: 2026-05-XX
- 加工: 8 秒にトリミング、フェードイン / アウト追加
```

### Play Store 提出時の注意

- CC BY 等の表示義務があるライセンスは、アプリ内クレジット表示が必要
- 設定画面に「使用ライセンス」セクションを設置（Phase 11）

## AlarmSoundCatalog の実装

`lib/domain/timer/alarm_sound_catalog.dart`:

ドメイン層に同梱音源のリストを定義。

```
class AlarmSoundCatalog {
  static const List<AlarmSound> all = [
    AlarmSound(
      id: 'default',
      displayName: 'デフォルト',
      assetPath: 'assets/sounds/alarm_default.mp3',
    ),
    AlarmSound(
      id: 'gentle',
      displayName: 'やさしい',
      assetPath: 'assets/sounds/alarm_gentle.mp3',
    ),
    // ...
  ];

  static AlarmSound get defaultSound => all.first;

  static AlarmSound? findById(String id) =>
      all.firstWhereOrNull((s) => s.id == id);
}
```

### 永続化との関係

- TimerEntity / Preset には `AlarmSound` ではなく **`String soundId`** で保存
- 表示時に `AlarmSoundCatalog.findById(soundId)` で解決
- 将来音源を追加・削除しても DB スキーマ変更不要

### ローカライズ

`displayName` は `application/` 層で `AppLocalizations` を使って多言語化することも可能。
ただし Phase 11 までは日本語固定で OK。

## ユーザー取り込み音源仕様（将来実装）

本節は、ユーザーが端末ストレージから任意の音源を選び、タイマー / アラーム /
プリセットで利用する機能の確定仕様を記録する。現時点では未実装であり、現在の
配信形態は引き続き「無料・広告なし・アプリ内課金なし」とする。買い切り枠は将来の
利用権限拡張に備えた設計上の予約であり、現行アプリで販売・提供するものではない。

### 同梱音源との仕様境界

- 本書「音源仕様」の 8〜15 秒、500 KB 以下、ピーク -3 dB 等は、品質を管理できる
  **同梱音源**に適用する。
- ユーザー取り込み音源には本節の容量・時間・形式制限を適用し、アプリ内での
  トリミング、変換、音量正規化は行わない。
- 通知 Channel の固定短音から選択音源へ 3200 ms で引き継ぐ既存方針は維持する。
  ハンドオフ時間は取り込み音源の再生時間に依存させない。

### 対応形式

初期対応形式は次のとおり。

| 拡張子 | 形式 |
| --- | --- |
| `.mp3` | MP3 |
| `.ogg` / `.opus` | Ogg Vorbis / Opus |
| `.wav` | PCM WAV（初期対応は 8 / 16-bit） |
| `.m4a` / `.aac` | AAC / M4A |

拡張子だけでは受け入れを判断しない。MIME type、ファイルヘッダー、実デコード可否を
検証し、形式または再生時間を確定できないファイル、破損ファイル、対応外 codec は
登録不可とする。再生時間は 1 秒以上かつ利用枠の時間上限以下とし、1 秒未満の音源は
登録不可とする。

### 利用枠と上限

容量単位は表示・内部判定とも `1 MB = 1,000,000 bytes` に統一する。

| 利用枠 | 1 ファイル容量上限 | 時間上限 | 登録可能件数 | 全音源の合計容量上限 |
| --- | ---: | ---: | ---: | ---: |
| 通常枠 | 5 MB | 3 分 | 3 件 | 15 MB |
| 将来買い切り枠 A | 10 MB | 6 分 | 5 件 | 50 MB |
| 将来買い切り枠 B | 15 MB | 9 分 | 10 件 | 150 MB |

全音源の合計容量上限は独立した設定値にせず、常に次式から算出する。

`1 ファイル容量上限 × 登録可能件数 = 全音源の合計容量上限`

合計容量はユーザーが取り込んだ実ファイルサイズの合計で判定する。同梱音源および
固定通知音は、登録可能件数と合計容量に含めない。

実装内部のファイルコピー、メタデータ取得、再生準備は、少なくとも 1 ファイル
25 MB / 15 分まで扱える構造とする。ただし、これは設計上の余裕であり、いずれの
利用枠でも受け入れ可能であることを意味しない。

将来拡張枠は買い切りで提供し、購入済み利用権限は恒久的に有効とする。商品構成、
価格、購入復元は課金機能の実装時に定める。

### 端末空き容量

- 判定対象は、アプリ内部保存先と同じストレージボリュームの総容量と空き容量とする。
- 取り込み開始前の空き容量が対象ボリューム総容量の 10% 未満なら追加不可とする。
- 取り込み後に空き容量が 10% 未満になると予測される場合も追加不可とする。
- コピー中に申告サイズを超過した場合は中断し、一時ファイルを登録しない。
- 容量取得に失敗した場合は安全側に倒し、追加せずエラーを表示する。
- 置換時は、旧音源と新音源を一時的に同時保持できる空き容量がある場合だけ実行する。

### 追加・管理 UI

- 既存の音源選択 sheet に「端末から追加」を設け、システムファイルピッカーを開く。
- 取り込み音源の一覧、試聴、改名、削除は独立した管理画面で行う。
- 初期表示名は元ファイル名から拡張子を除いた文字列とし、取り込み後に改名できる。
- 取り込み確定前と管理画面の両方でプレビューできるようにする。
- プレビューは本番鳴動と同じアラーム音量経路を使い、画面を閉じたとき、別音源を
  再生したとき、取り込みを確定または中止したときに停止する。
- 内容ハッシュで同一内容の重複を検出し、既存音源を案内して二重登録しない。

### 削除と参照整合性

- Timer / Alarm / Preset / デフォルト設定から参照中の音源も、確認後に削除できる。
- 削除時は対象 `soundId` を参照する全レコードとデフォルト設定を、同梱デフォルト音の
  `soundId` へ一括置換してから実ファイルとメタデータを削除する。
- 一括置換またはファイル削除に失敗した場合に中途半端な参照を残さないよう、DB 更新と
  ファイル削除の失敗補償を設ける。
- 起動時や鳴動時にも解決不能な `soundId` は同梱デフォルト音へフォールバックし、
  削除処理外の破損や欠損にも備える。

### 取り込み・永続化

1. Android のシステムファイルピッカーでユーザーが 1 ファイルを選択する。
2. 形式、実デコード可否、ファイルサイズ、再生時間、内容ハッシュ、利用枠、
   端末空き容量を検証する。
3. 検証済みファイルをアプリ内部ストレージの一時ファイルへコピーする。
4. DB には安定した `soundId` と、表示名、形式、実ファイルサイズ、再生時間、
   内容ハッシュ、アプリ内保存先を解決するための情報を保存する。
5. DB 登録と最終ファイルへの確定が両方成功した場合だけ取り込み完了とする。失敗時は
   DB の未確定レコードと一時ファイルを削除する。
6. Timer / Alarm / Preset は既存と同様に `String soundId` だけを保持する。

コピー元 URI や外部ストレージ上の絶対パスを Entity に保存しない。元ファイルの
移動・削除、SD カードの取り外し後も鳴動できるよう、再生はアプリ内部コピーを使用する。
取り込み音源が削除済み、破損、または再生不能の場合は同梱デフォルト音へ
フォールバックする。

通知からのコールド起動時も、静的な同梱カタログだけでなく取り込み音源 Repository を
初期化し、Entity の `soundId` からアプリ内部コピーを解決する。初期化、Entity 取得、
音源解決のいずれかに失敗した場合は同梱デフォルト音を使用する。

取り込み音源は初期実装では OS バックアップおよび端末移行の対象外とする。
アプリをアンインストールした場合、内部コピーとメタデータは削除される。将来対応する
場合は、音源本体の容量、購入済み買い切り権限の復元、権利責任を含めて別途設計する。

ユーザーが取り込んだ音源の権利責任はユーザー自身にあり、同梱音源向けの
`assets/sounds/LICENSES.md` には記録しない。取り込み音源は端末内利用に限定し、
アプリから外部送信しない。

### 制限値の設計

5 MB / 3 分等を UI や処理へ散在してハードコードしない。Application 層へ、現在の
利用権限から解決した次のポリシー値を渡す。

- 1 ファイル容量上限
- 時間上限
- 登録可能件数
- 対応形式

課金 SDK、商品 ID、買い切り商品名は Domain に持ち込まない。合計容量上限はポリシーの
「1 ファイル容量上限 × 登録可能件数」から導出し、表示と登録判定で同じ値を使う。
詳細な設計判断は `docs/adr/0006-user-imported-sound-policy.md` を参照する。

## 通知音との関係

### Android の通知音

通知 Channel に設定した音は `assets/` から直接読めない。
代替案:

1. **`android/app/src/main/res/raw/` に配置**
   - 通知 Channel の `setSound()` で参照可能
   - ただし assets と二重管理になる

2. **通知音は標準 + アラーム画面起動後にカスタム音再生**（採用）
   - 通知 Channel: 固定の短い通知音
   - 通知音の再生中に `audioplayers` で選択音源を prepare
   - 固定ハンドオフ境界後に選択音源のループ再生を開始

3. **通知音なし + バイブ + フルスクリーン Intent**
   - 通知時点では音を鳴らさず、画面遷移後に鳴らす
   - フルスクリーン Intent 失敗時は無音になるリスク

### 採用方針

**案 2** を採用。理由:
- assets 一元管理
- アラーム画面のスヌーズ / 停止操作と音再生のライフサイクルが一致
- 通知音は短い「タンッ」程度で OK（あくまで存在通知）
- OS 通知音の長さとユーザー選択音源の長さを分離できる
- Stop / Snooze は待機中の再生世代も無効化し、遅延開始を防止できる

ただし通知のみで気付かせたいケース（ロック画面に出ない場合）があるため、`res/raw/` に固定通知音 `notif_alert.mp3` を配置する。Pixel 6a / Android 16 の実測では OS 音の完了が Flutter 側の引き継ぎ開始から 2.97〜3.12 秒後だったため、Application 層の固定ハンドオフ値は 3200 ms とする。この値はユーザー選択音源の再生時間には依存しない。

```
android/app/src/main/res/raw/
├── notif_alert.mp3   // 通常タイマー／アラーム Channel 用、約2秒
└── alarm_default.mp3 // 定間隔通知 Receiver 用（Native側で再生時間を制限）
```

## ファイル命名規則

### 音源

- 形式: `<category>_<name>.<ext>`
- 例: `alarm_gentle.mp3`, `notif_alert.mp3`
- すべて小文字、スネークケース

### カテゴリ

| カテゴリ | 用途 |
|---|---|
| `alarm_` | タイマー鳴動用（ループ再生） |
| `notification_` | 通知音（短時間、単発） |

## アセット追加・削除のフロー

新規音源追加時:

1. ファイルを `assets/sounds/` に配置
2. `assets/sounds/LICENSES.md` にライセンス情報を記載
3. `lib/domain/timer/alarm_sound_catalog.dart` に追加
4. ユニットテスト（catalog のエントリが正しく取得できるか）
5. 実機でループ再生確認

削除時:

1. **DB 上に該当 soundId を持つレコードがある可能性**を考慮
2. `AlarmSoundCatalog.findById()` が null を返した場合、デフォルト音にフォールバック
3. ファイルと catalog エントリを削除
4. マイグレーションスクリプトは不要（findById のフォールバックで対応）
