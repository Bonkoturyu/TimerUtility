# 難タスク実行プロトコル

要求解釈、計画、統合、最終判断はメインエージェントが保持する。

## 着手前

1. `AGENTS.md`、`tasklist.md`、`BACKLOG.md`と、依頼へ直接関係する`docs/`だけを読む。
2. 完了条件を次の3点で定義する。
   - 変更対象ファイル
   - 期待する静的結果と自動テスト
   - ユーザーまたは実機で確認する事項
3. 未知を列挙し、既存コード、設定、履歴、実時間API、公式資料から解消できるものを先に調べる。
4. 作業を独立に検証できる主張へ分け、3ステップ以上なら計画管理へ外部化する。
5. 編集に確認が必要なファイル、ADR・`docs/`との矛盾、新規依存、Native変更、権限追加の有無を確認する。該当時は`AGENTS.md`に従って停止する。

## 実行中

各検証境界で次を確認する。

1. 得られた証拠が予測と一致するか。
2. 新しい証拠を得た後も残りの計画が有効か。
3. 依頼の完了条件へ近づいたか。

同じテストが3回連続で失敗したら停止する。同一ファイルを5回以上連続編集する兆候、または100行を超える新規コードが必要になった場合も、`AGENTS.md`のAuto停止条件に従う。無関係な問題は修正せず記録する。

## SubAgent

- 明確な対象、禁止範囲、受入条件、検証を持つ独立作業だけを委譲する。
- 同一ファイルを複数Agentで同時編集しない。
- SubAgentによる再帰委譲を禁止する。
- 要件解釈、アーキテクチャ判断、成果物の統合、最終検証、Git判断、ユーザー報告はメインエージェントが行う。
- Opus 5へ委譲する場合は`delegate-to-claude` Skillを使用する。

## 検証境界

変更内容に応じて、実行可能なものを選ぶ。

- `dart format --set-exit-if-changed .`
- `dart run tool/check_translations_doc.dart`
- `flutter analyze --fatal-infos`
- `flutter test`
- 対象を限定したUnit Test、Widget Test、Integration Test
- `git diff --check`

Android実機、Doze、FullScreenIntent、通知、アラーム音、署名済みビルドなど、ローカル環境だけで完了できない確認は成功扱いにせず、具体的な確認手順とともに未検証として残す。

## 完了前

1. `git diff`を第三者の変更として読み直し、巻き込み、規約違反、デバッグコード、機密情報を探す。
2. 実施した検証を成功・失敗・未実施に分ける。
3. 最初の完了条件と依頼文を項目ごとに照合する。
4. `tasklist.md`を実態へ同期する。
5. ユーザー判断事項を、確認手順または確認対象とともに報告する。
